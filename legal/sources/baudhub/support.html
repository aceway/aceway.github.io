BaudHub

Modbus RTU/TCP Serial Debugger for Mac
Read • Explain • Write Safely

Purpose

BaudHub is a native Modbus RTU and Modbus TCP debugger and serial terminal for Mac. Connect an RS485 or RS232 serial adapter or a Modbus TCP device, read register values quickly, see the exact frame behind every value, and change settings safely with automatic read-back. A built-in Modbus slave simulator lets you test a PLC, SCADA system or master without hardware.

BaudHub is made for commissioning engineers, PLC and SCADA integrators, solar, battery, EV charger and heat pump installers, energy meter technicians, and embedded and IoT developers. No account, no analytics, no ads.

Key Features

  • Modbus master: RTU over serial and Modbus TCP; coils, discrete inputs, holding and input registers; single and multiple writes
  • Adapters: serial adapters with FTDI, CP210x, PL2303 or CH34x chips, with a hint when one needs a driver
  • Decoding: 28 display formats, including integers, float, BCD, hex and ASCII, with byte order, address base, scaling and units
  • Raw data: each value in several formats side by side, with the raw HEX and the frame it came from
  • Frame log: requests, replies, errors and timeouts explained in plain language, with filters, search and CSV export
  • Bus scan: unit IDs, baud rates and parity, plus a guided unit address change
  • Safe writes: read-only by default; every write is previewed, confirmed, checked by reading the value back and logged
  • Charts: live series with time windows, thresholds and a link from any sample to its frame
  • Slave simulator: Modbus RTU and TCP slave with several unit IDs and changing values
  • Serial terminal: ASCII and HEX, timestamps, send history and recording
  • Templates: SunSpec, SMA, Fronius, SolarEdge, KOSTAL, KEBA, go-e, Chint DDSU666/DTSU666, Schneider PM5xxx and Eastron SDM630
  • Field-ready: values that stop updating are clearly marked, BaudHub reconnects after the adapter is plugged back in or the Mac wakes, and sessions export as one package
  • User guide: a step-by-step guide in English, German and Simplified Chinese, built into the app

Requirements

• Requires macOS 26 or later; runs natively on Apple silicon and Intel Macs.
• English, German and Simplified Chinese, following your macOS language.
• Serial devices need an RS485 or RS232 adapter that shows up as a serial port on your Mac. Adapters with a USB-C plug connect directly; USB-A plugs need a USB-C adapter or hub.
• Modbus TCP devices need to be reachable from your Mac, usually on port 502; check the device manual for its port.
• Works without an internet connection; purchases and restores use the App Store.

Getting Started

  1. Plug in your adapter, or make sure your Mac can reach the device's IP address.
  2. Choose Serial or TCP in the middle of the toolbar, then click + next to Connections (⌘N). For serial, pick the port and enter the device's baud rate, data bits, parity and stop bits (often 9600 8N1). For TCP, enter the host and port.
  3. In Add Device, enter the unit ID and choose a template, or add a register block with the function, start address, count and format from the vendor's register map.
  4. When the device answers, its value appears in the list. Select a row to see the value in other formats and the raw data it came from.

Don't know the unit ID or line settings? Choose ⋯ More › Scan above the register table (⌘F). For every step in detail, open Help › BaudHub User Guide in the app.

Troubleshooting

My serial port is not in the list

Plug the adapter in and click the refresh button next to Port. If BaudHub shows Driver needed for …, the chip (often CH343, CH9102 or a newer PL2303) needs the vendor's driver: install it from the link and replug the adapter. Using an adapter or hub in between? Try another port or connect without it. Still nothing? Try another cable; some cables only charge.

"Port in use"

Another app or BaudHub instance holds the port, for example screen, the Arduino IDE or another debugger. Close it there and retry.

Connected, but no values

Open the Frame Log tab and look at the colors:

  • Yellow (timeout): the device did not answer. Check the unit ID (or scan), swap A and B, and confirm the device has power.
  • Red (garbled reply): the baud rate or parity usually differs from the device. Compare with its nameplate.
  • Orange (exception): the device is online but refused the request, usually an address out of range or the wrong function (input vs holding registers).
  • Grey: data arrived without a request; another master may be active on the bus.

A Modbus TCP connection is refused or reset

Many inverters and gateways accept only one Modbus client at a time, so disconnect other software connected to the device first. Check that Modbus TCP is enabled on the device, that the IP address and port are right, and that your Mac and the device are on the same network. If macOS asked about local network access, allow BaudHub in System Settings › Privacy & Security › Local Network.

Values look wrong

Absurd numbers usually mean the wrong format or byte order: select the row and compare the same value shown in other formats. Values off by 10× or 100× need a scale factor. Values that belong to the neighboring register point to a 0- vs 1-based address mix-up.

Write is unavailable

Unlock writes with ⋯ More › Read-only above the register table (⌘L). Writes also stay unavailable while disconnected, on registers marked read-only, in imported sessions, and on the Free plan. The lock closes again after every reconnect.

Everything turned grey

The link dropped, for example after an unplug, a device restart or sleep. BaudHub reconnects on its own; grey values are kept but marked stale until fresh replies arrive.

Another computer cannot reach my simulator

Use one of the listen addresses the simulator shows, check that macOS Firewall allows BaudHub, and make sure the simulator is still running.

Frequently Asked Questions

What is the difference between Modbus RTU and Modbus TCP?

Modbus RTU runs over a serial line such as RS485 or RS232. Modbus TCP carries the same requests over Ethernet or Wi-Fi. BaudHub supports both; this version does not open Modbus RTU over TCP connections.

Is there a Modbus Poll alternative for Mac?

BaudHub is a native Mac app for reading, writing and scanning Modbus devices, with a slave simulator and a serial terminal, so you don't need to run Windows tools in a virtual machine.

Can I test without a device?

Yes. Switch to Simulator mode, click Add Modbus TCP and start the simulator. Then connect to it from BaudHub, or from your own master, PLC or SCADA system, using the address the simulator shows. To try Serial mode without an adapter, click Add Virtual RTU instead: that simulator sits on a virtual serial line only BaudHub sees, and Connect in Serial Mode… opens a connection to it.

Can I run two jobs at the same time?

Yes. Choose File › New BaudHub Instance to open another BaudHub with its own workspace, for example one for a serial bus and one for a TCP gateway.

Are the device templates verified?

Each template names the vendor document it was built from and says when it has not been tested on a real device. Check important registers against your device's documentation before writing. Vendor names identify register maps only; BaudHub is not affiliated with these companies.

What does a session export contain?

Export Session… saves your connections, devices, register settings, readings and logs as a single file you can share. Imported sessions open read-only.

Where can I find the user guide?

In BaudHub, open the Help menu in the toolbar and choose BaudHub User Guide. The guide opens in your language (English, German or Simplified Chinese) and works offline.
